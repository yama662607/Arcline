# 05. プロジェクト仕様書（AIエージェント向け）

## 1. プロジェクト名

**Arcline**

## 2. 目的

Chromiumベースのブラウザで、Arcブラウザにインスパイアされた、モダンで高性能な垂直タブ拡張機能を開発する。特に、`sidePanel` APIが利用できないブラウザ（Arc, Atlasなど）でも、代替UIにより可能な限り近い体験を提供することを目指す。

## 3. 主要機能（MVP）

1.  **垂直タブUI**: タブの一覧表示、検索、D&Dによる並べ替え、ピン留め機能。
2.  **スペース管理**: タブの集合を「スペース」として保存・復元・休止する機能。ブックマークフォルダと連携させる。
3.  **コマンドパレット**: `Ctrl/Cmd+K`で起動。スペース、タブ、履歴（オプトイン）を横断検索し、即座に移動する。
4.  **フローティングUI**: 画面左端へのホバー（またはクリック）でUIが出現・消失する、Arcライクな体験を再現する。
5.  **設定機能**: お気に入りボックスのレイアウト、サイズ、密度などをユーザーがカスタマイズできる。

## 4. 技術スタック

-   **言語**: TypeScript
-   **フレームワーク**: React
-   **状態管理**: Zustand
-   **ビルドツール**: Vite
-   **パッケージ管理**: pnpm (ワークスペース利用)
-   **テスト**: Vitest (ユニット), Playwright (E2E)
-   **スキーマ定義**: Zod

## 5. アーキテクチャと実装方針

-   **Manifest V3**に準拠し、Service Workerを中心としたイベント駆動アーキテクチャとする。
-   **UIの表示戦略**: `chrome.sidePanel`が利用可能か動的にチェックする。
    -   **利用可能な場合**: `sidePanel`を主UIとして使用する。
    -   **利用不可能な場合**: コンテンツスクリプトによる「ページ内フローティングUI」にフォールバックする。`chrome://`ページなど、コンテンツスクリプトが動作しない場合は、ツールバーアイコンのクリックでポップアップウィンドウを表示する。
-   **パフォーマンス**: UIのリスト表示には**仮想リスト**を必ず使用し、大量のタブがあってもスムーズな描画を維持する。アニメーションは`transform`と`opacity`のみを使用する。
-   **状態管理**: Zustandのストアは関心事ごとにスライス（分割）し、UIコンポーネントはセレクタを使って必要なデータのみを購読すること。
-   **設定システム**: Zodでスキーマを定義し、グローバル設定 (`storage.sync`) とスペースごとの上書き設定 (`storage.local`) をマージして適用する。

## 6. ライセンスとリポジトリ

-   **ライセンス**: 元プロジェクト(Arcify)を継承し、**GPL-3.0**とする。
-   **リポジトリ**: 当初はプライベートリポジトリで開発を進め、MVP完成後にパブリックに公開する。
-   **法的要件**: UI内にGPLライセンスに基づく著作権、無保証、ソースコードへのリンクを明記した「About」セクションを設けること。

## 7. 開発・CI/CD

-   **コミット規約**: Conventional Commitsに従うこと。
-   **CI**: GitHub Actionsで、lint, 型チェック, テスト, ビルドを自動実行すること。
-   **CD**: `main`ブランチへのマージ時に`semantic-release`を使い、バージョニング、CHANGELOG生成、GitHubリリース作成を自動化すること。

## 8. AIエージェントへの指示

上記仕様に基づき、**Arcline**のMVP開発を開始してください。まずは、リポジトリのセットアップ、ViteとTypeScriptの導入、そして主要なUIコンポーネントの骨格作成から着手してください。
