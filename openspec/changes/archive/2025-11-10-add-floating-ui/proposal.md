# 変更提案: Atlas 向けフローティング UI の追加

## Change ID
`add-floating-ui`

## 概要
- Atlas など `chrome.sidePanel` をユーザージェスチャー付きでも開けないブラウザ向けに、React 垂直タブ UI をページ内に表示するフローティング UI を実装する。
- 画面左端のホットゾーンにカーソルを合わせると UI がアニメーション付きでスライドインし、離れると自動的に閉じる Arcify ライクな体験を提供する。
- 既存の React 垂直タブ UI を流用しつつ、初期ロードサイズ・描画コストを抑えるための分割読み込みとパフォーマンス指標を整備する。
- `chrome://` などコンテンツスクリプトが動作しないページでは、従来どおりポップアップ UI にフォールバックするフローを明確化する。

## 動機
- Atlas では Side Panel API が実質利用できないため、サイドパネル UI だけでは Arc/Arcify と同等の UX を届けられない。
- 現在の React UI は Side Panel 利用を想定しているが、Atlas でも同じレイアウトを保ったまま快適に利用できる導線が必要。
- 既存の change `refactor-react-migration` はスコープが大きく、フローティング UI を切り出すことで計画と実装を段階的に進めやすくする。

## スコープ
### In Scope
- サービスワーカーによる UI モード判定に「フローティング UI」モードを追加し、Atlas などで選択するロジックを実装。
- コンテンツスクリプト経由でホットゾーンと Shadow DOM 内の React 垂直タブ UI を描画する。
- ホットゾーン hover で出現、離脱で自動クローズするアニメーション挙動を実装。
- 既存の React 垂直タブ UI レイアウト（Arcify のボタン配置）を維持しつつ、遅延読み込みやコード分割で軽量化指標を満たす。
- Atlas 等でコンテンツスクリプトが実行できないタブでは、ポップアップ UI へ誘導するフローを追加。
- docs/browser-compatibility.md や開発ガイドに Atlas モードの仕様を追記。

### Out of Scope
- 新しいタブ UI デザインへの刷新（配置の微調整以上の変更）。
- Atlas 固有の追加 API 連携や AI 機能統合。
- TanStack Query 等の導入本番化（基盤整備は既存 change に委ねる）。

## 影響
- **ユーザー**: Atlas でホットゾーン hover だけでタブ UI が表示され、Arcify に近い操作感を得られる。
- **開発者**: サイドパネル用 React UI を流用できるが、コード分割・モード切り替えなど考慮点が増える。分割によりメンテナンス性が向上。
- **パフォーマンス**: 初期ロードサイズ 180KB 以下、hover から表示まで 150ms 以内、非表示中は待機タイマー無しといった指標を満たす必要がある。

## リスク / 依存関係
- コンテンツスクリプトは全ページで動作しないため、フォールバック漏れに注意。
- React 垂直タブ UI を共有することで、表示モード間のスタイル衝突や状態共有の設計が複雑になる可能性。
- 既存 change (`refactor-react-migration`) と並行作業になるため、Zustand ストア構造など最新設計との整合を確認する必要がある。
